## 1. 录制前准备（所有三段共用）

### 1.1 不要覆盖仓库里的存档日志

各脚本默认把日志写到仓库的 `logs/`、CSV 写到 `bench/results/`、图写到 `docs/stage3/figures/`，**录屏时重跑会覆盖存档证据**
（例如 `03_run_hello.sh` 会把新 IP 写进 `logs/stage1/p1_hello_xiangshan.log`；用 GCC 15 重跑 `40` 会让 3 个 CSV 的 `minstret` 绝对值 +2）。
录屏前在每个终端先设置：

```bash
cd <仓库根目录>
export REC=/tmp/rec                      # 录屏专用输出目录（路径尽量短）
export LOG_ROOT=$REC/logs                # 日志不写回仓库 logs/
export RESULTS_DIR=$REC/results          # 40 的 CSV 不写回 bench/results/
export FIG_DIR=$REC/figures              # 40 的图不写回 docs/stage3/figures/
mkdir -p $LOG_ROOT $RESULTS_DIR $FIG_DIR
```

录完后执行 `git status --short`，确认 `logs/`、`bench/results/`、`docs/stage3/figures/` 没有被改动；若有，用 `git checkout -- <路径>` 还原后再提交任何东西。

### 1.2 WORK_DIR 的选择

- **录屏①（演示从零部署）**：用一个全新的短路径工作目录，例如 `export WORK_DIR=/tmp/rec/w`。
  路径要短：上游 yunsuan `emu.cpp` 用 `getcwd(cwd, 64)` 拼波形路径，`${WORK_DIR}/XiangShan-kmhv2/yunsuan` 超过 63 字节时 `WAVE=1` 会报错（`docs/_plan/HANDOFF_TODO.md` 第二节「已知限制」）。
- **录屏②③**：沿用已经跑通的工作目录（默认 `<仓库根>/work`，即不设 `WORK_DIR`），避免重新克隆与构建。

### 1.3 依赖与环境变量

- 依赖缺失时 `00_setup_env_host.sh` 会打印对应的 `apt-get` 命令后退出；无 root 权限时用 `LOCAL_SYSROOT=1 bash scripts/00_setup_env_host.sh`。
- 每个新 shell 先执行 `source scripts/env_host.sh`（载入 JDK 17、mill、espresso 路径）。
- Linux 上 `XS_RUNNER` 默认 `auto` = 宿主机直接执行，不需要 Docker；`01_setup_env_docker.sh` 录屏中**不演示**（只在 macOS 上需要）。
- 可选：`export JOBS=<核数>` 控制并行度。
