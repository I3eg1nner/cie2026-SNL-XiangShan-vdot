## 3. 语义裁定史：验证过程如何改进了设计

1. **D2（立项）**：定义三条指令的编码与语义，`vdot.vv` 对应赛题，`vdotacc.vv` / `vdot4a.vv` 为共享数据通路的扩展；
   `vstart` / `vl` / `vm` / `vta` 行为留待逐项裁定。
2. **D2.1（P3 参考模型阶段）**：在写 C 参考模型 `tests/golden/vdot_ref.c` 时做出 S-1…S-9 共九条裁定。其中
   **S-1**：`vdot` / `vdotacc` 属归约类，`vstart != 0` 抛非法指令（RVV 1.0 §14）；
   **S-7**：`vdot4a` 是逐元素指令，按 RVV 一般规定 `vstart` 正常生效（prestart 元素保持不变）。
   设计文档当时已注意到香山译码会在 `vstart != 0` 时拦下所有向量算术指令，但把它登记为「全核上不可达的一处」（`10` §9 R-06），
   而没有修订 ISA 定义。参考模型、NEMU、RTL 数据通路随后都按 S-7 实现，FU 级测试与 NEMU 自测全部通过——
   因为它们比较的两端都出自同一套裁定。
3. **P4 功能测试**：发现香山译码侧不拦截 `LMUL != 1` 的 vdot（会静默算错），在实现树补 `dotEmulIllegal` 守卫（`11` §10 第 8 条）。
4. **P6 协同仿真首轮**：真实 NEMU `.so` 与香山译码单元（含**上游未改动的** `VecExceptionGen`）逐条比对，报出 **6415 条**判定分歧：
   G5a（LMUL≠1，4469 条，协同仿真工作树快照尚未同步上述守卫；换用对齐寄存器 `v8/v16/v24` 后才完整暴露）与
   G5b（`vdot4a` + `vstart ∈ {1,2,3}`，1946 条）。G5b 证明错的不是任何一处实现，而是 S-7 本身比目标微架构允许的更宽。
5. **D2.3（裁定 S-7'）**：按「平台约束优先原则」让 ISA 向微架构收敛——`vdot4a` 在 `vstart != 0` 时同样抛非法指令。
   RTL 一行未改（上游 `vstartIllegal` 本就覆盖）；传播链为参考模型 → 语料重新生成（1545 条 `OK → ILLEGAL_VSTART`）→
   NEMU `vdot.c` 补一行 `check_vstart_exception` → 设计/参考模型/NEMU/协同仿真文档 → 重跑 P4/P5/P6/P7。
   复跑后判定分歧 **6415 → 0**，并由故障注入 `T3-NEMU-3` 守护（删掉那一行即重新出现 74 条分歧）。
6. **P7 基线等价性的独立印证**：基线只能用标准 RVV 指令，而这些指令在 `vstart != 0` 时一律 trap；首轮基线测试因此报出
   1553 条「基线不可表达」用例，从另一条独立路径指向同一问题，S-7' 之后归零（`22` §3.3）。

**结论**：自写黄金模型对比自写 RTL，在结构上发现不了「规范本身错了」这类问题；只有当比较的一端是**不由我们编写**的语义
（香山上游译码判据）时，裁定的偏差才会暴露。完整论证见 `docs/stage3/21_协同仿真验证报告.md` §7.5、
`docs/stage2/13_参考模型与测试向量说明.md` §7「裁定的修订历史」、`docs/stage2/10_vdot指令设计文档.md` §1.5.4。
